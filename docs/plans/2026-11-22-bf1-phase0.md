# BF1 native port — phase 0 plan

## Goal

Bring up an offline, single-player native PC port of Battlefield 1 (CUSA02429, v1.00),
using SpartanPort's fast runtime as the base. No PSN / real PS4 server connectivity in phase 1.

## Sources

- Base: upstream `FelipePrado0/SpartanPort` (performance-focused native runtime + shadPS4 video core).
- Donors: upstream `GNSB/UFC-3-PS4-PORT` (Frostbite/EA), `yerasuu/psport` (module-loader patterns only),
  `HajDEO/nhl24pc` (Frostbite GPU fixes), plus useful shadPS4 PRs/forks/commits when applicable.
- Reference: local shadPS4 fork branch `fix/exact-depth-copy-buffer-size` and its logs in
  `/tmp/opencode/bf1/`.

## What shadPS4 testing already established

- BF1 boots to title, main menu, and first-person campaign gameplay at 1920x1080.
- Three emulator fixes were needed:
  1. exact-size staging buffer for depth/color copies (avoids 128 MB constant allocations),
  2. texture images unmapped on the GPU thread (avoids `UnregisterImage` race),
  3. optional frame-locked GPU clock to keep DRS pinned high.
- GPU saturation, not a memory leak, causes FPS collapse when resolution is forced to 1080p
  (GPU busy 100%, RSS plateaus ~6.3 GB, VRAM oscillates 4.5-6.7 GB, no thermal throttle).
- Black-world / green-tint episodes are stale render-target/post-process state after scene resets;
  checkpoint restart recovers them.
- EAWebKit crash: `sceKernelStopUnloadModule` is stubbed and `LoadStartModule` dedupes by filename,
  so a second WebBrowser session reuses torn-down state (null hash-table bucket).
- Controller hotplug in this container needed `SDL_JOYSTICK_HIDAPI=0` and
  `SDL_JOYSTICK_DISABLE_UDEV=1`; cold start works.

## Phase 0 tasks

1. Verify the unmodified upstream base builds on this host (`bash build.sh`).
2. Inventory BF1's eboot and bundled PRXs: imports, NIDs, module bases, load/unload events.
3. Decide module strategy: offline-link always-present modules; implement a minimal runtime
   loader only for modules BF1 actually loads dynamically (EAWebKit, JavaScriptCore, codecs,
   sysmodules). Real unload must run fini/clear state.
4. Decide the GPU bring-up path: reuse vendored shadPS4 `video_core`, fold in UFC3/NHL24pc
   Frostbite fixes only as needed.
5. Stub NP/PSN/network libraries as offline; campaign must not depend on services.
6. Define test milestones: boot -> title -> main menu -> checkpoint -> first gameplay frame ->
   stable 10-minute offline session.

## Build status (2026-11-23)

- Upstream base builds on this host: `bash build.sh` produced `out/spartanport-probe`,
  `out/spartanport-gpu-capabilities`, and `out/gpu/libspartanportgpu.so`.
- Host packages needed beyond the shadPS4 toolchain: `SDL3-devel`, `ffmpeg-free-devel`,
  `fmt-devel`, `boost-devel`, `robin-map-devel`, `xxhash-devel`, `glslang`,
  `VulkanMemoryAllocator-devel`, `zydis-devel`.
- Fedora ships Zydis binaries but no CMake package config; a local shim at
  `/tmp/opencode/cmake/ZydisConfig.cmake` defines `Zydis::Zydis` and `Zycore::Zycore`
  for `CMAKE_PREFIX_PATH`. This is host-only, not committed.
- `build.sh` applies patches to the `fsr-vulkan` submodule working tree; expected, not committed.

## Out of scope for phase 1

- Real PSN / PS4 servers / matchmaking / online multiplayer.
- Shipping any game files or decompiled game code (users must supply their own dump).
